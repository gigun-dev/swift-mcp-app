# ジェスチャ・指追従の実装ルール(gesture/drag/アニメーションを触るとき必読)

drawer 境界のカクつき(2026-07-23 軸ロック修正)のような「追従が跳ねる」不具合を
繰り返さないための原則。詳細な経緯と根拠は docs/design/07-interaction-gesture-principles.md。

1. **判定は one-shot、追従は連続。** 「このジェスチャは横か縦か」「開始位置は許可帯か」の
   ような**分類判定**は、ジェスチャ開始時(最初の onChanged)に一度だけ行い、ジェスチャ中は
   固定する(UIScrollView の direction lock と同じ)。累積 translation を毎フレーム再判定に
   使ってはならない — ゆっくりしたドラッグでは累積量が拮抗し、判定反転のたびに出力が跳ぶ。
2. **指追従中の出力値は入力に対して連続にする。** onChanged が返す offset/translation が
   前フレームから不連続にジャンプする分岐(「条件を満たさないから 0 に戻す」等)を書いたら
   設計を疑う。丸め(clamp)は連続、リセット(=0)は不連続。
3. **判定ロジックは Kernel の純関数に置き、連続性をテストで固定する。** 新しい判定を足すときは
   「単調に動く指の入力列に対して出力列が跳ばない」ことを表すテストケースを必ず添える。
4. **ライブ追従に withAnimation を混ぜない。** アニメーションは onEnded の確定遷移だけ。
   onChanged 中の値は素の state 代入で指へ直結する(暗黙アニメーションが追従遅延・波打ちを生む)。
5. **ドラッグの translation は、そのドラッグで動くビューの座標空間で測らない。** offset 適用 →
   空間移動 → translation 逆補正のフィードバックループが毎フレーム振動(進む→戻るの2周期)を生む。
   translation・startLocation は offset の外側の named 空間で測る(DragGesture の `coordinateSpace:` と
   ビュー側の `.coordinateSpace(name:)` を offset を持たない祖先に置く)。振幅≒速度×遅延なので
   速いフリックでは知覚されず、ゆっくりドラッグで露見する(P1 と同じ「速い操作では正常」シグネチャ)。
